# Experimental vision evidence

## Completed balanced precision/recall follow-up

The target of both eight-class Precision and Recall ≥70% was **not met**. The selected `new_best832` at confidence 0.25 and class-aware IoU≥0.5 achieved micro P/R/F1 **50.52% / 52.00% / 51.25%**, versus parent640 **48.62% / 51.20% / 49.88%**: small gains of 1.89/0.80/1.37 percentage points. Macro P/R/F1 were 42.02%/43.52%/42.62%; the sunken-alligator class declined from 36.99%/35.06%/36.00% to 24.49%/31.17%/27.43%. No class met both 70%, and none of the four candidates met the micro target within the preregistered grid.

The [frozen plan](balanced70_plan.json) preserves the single additional 40-epoch budget and validation-only selection. [Summary](balanced70_summary.json), [four-candidate operating points](balanced70_operating_points.csv), [actual 40-epoch training results](balanced70_training_results.csv), [PR curves](balanced70_pr_curves.png) and [eight-class comparison](balanced70_per_class.png) preserve the completed evidence without dataset photographs or model weights. The [supervisor acceptance report](../../../Miscellaneous/BALANCED_VISION_OPTIMIZATION.md) reports every class support/P/R/F1, errors, rare-type counts and separate IoU0.3/class-agnostic/family diagnostics. These diagnostic modes do not replace the eight source types or satisfy the primary target.

Training used clean commit `bec6fb33d594544d00d06cbfb4ffeb74722cd138`, one seed 42, imgsz 832, actual batch 16/nbs 64 and took 4,762.9 seconds. The library-selected best checkpoint is epoch 10; last is epoch 40. Native validation mAP50/mAP50–95 were 40.16%/20.27%, compared with the parent's 38.77%/20.23%; native curve P/R differ from the fixed-confidence micro counts above. Several settings changed together, so the small improvement has no single-parameter causal or statistical-significance claim.

Acceptance recorded real high-resolution/class-weighted recovery smoke, 761 regression tests passed with one additional Windows symlink-permission skip, 44 guard tests, finite checkpoint/recovery tensors, 39,674 train/val file SHA256 checks and 11 isolated HTTP response cases. Both metric plots, four contact sheets covering 40 stratified images and three full-size fixed comparisons were visually reviewed. No candidate test images or labels were opened this round; test split metadata was used only to verify group isolation. Validation had already been used for training/model selection, so this remains validation-tuned evidence rather than a fresh holdout claim. Directed error examples are exploratory, and no annotation defect was confirmed or corrected.

Full evidence remains under ignored `Dataset/balanced70/` and the actual run directory, including selection, integrity, selected-errors and HTTP summaries. The local selected manifest (`Dataset/balanced70/selected_model_manifest.json`) is opt-in only: it does not change PyCharm settings, environment variables or a running backend, and all nonempty real detections still require review. Applied cleanup removed only train.cache (4,344,707 bytes) and val.cache (452,896 bytes), releasing 4,797,603 bytes (4.80 MB / 4.58 MiB); all datasets, prediction exports and old/new best/last/latest/previous checkpoints were retained. Further improvement should begin with auditable label consistency and rare-type support work while preserving all eight types.

## Historical 10-epoch baseline

`step8_baseline_summary.json` contains actual 2026-10-13 run metadata, frozen split counts, source/checkpoint hashes, native Ultralytics eight-class validation and held-out test metrics, recovery evidence, HTTP acceptance and cleanup counts. `baseline10_results.csv` records the ten completed epochs. These small summaries are committed; images, weights, prediction exports, databases and full logs remain in ignored `Dataset/`.

The JSON `configuration` object is the exact `Dataset/baseline10-config.json` used for training: YOLO11n transfer, seed 42, 10 epochs, image size 640, batch 32, AdamW with lr0 0.001, CUDA device 0. The generic 30-epoch example is separate from both this historical baseline and the later frozen compare30 configurations above. On a new machine follow the [data pipeline](../../model/data_readme.md) and [training guide](../../model/TRAINING.md); paths in regenerated YAML and their digests will be machine-specific. Use a new run name for another experiment; do not overwrite completed evidence or extend a completed run through resume.

Training occurred on uncommitted implementation code. `training_runtime.git_commit` is the base commit, with `git_dirty:true` and source hashes identifying the actual files. Dataset/YAML input validation was tightened after training; model/data/optimizer/evaluation were unchanged. Do not claim that the base commit alone reproduces this run.

Metrics remain experimental. `map50` and `map50_95` are detection average precision, not the fraction of correctly classified photographs. P/R/F1 are descriptive points on each split's PR curves; the test split did not select the model or inference threshold. Confusion counts were collected at evaluation confidence 0.001 and must not be interpreted as deployed confidence 0.25 counts. No optional faster-coco-eval result is claimed. Dataset images do not establish Jurong geography, road permission or engineering severity. All real nonempty detections require review and tasks still use demo business rules.

See the [supervisor acceptance record](../../../Miscellaneous/STEP8_VISION_ACCEPTANCE.md) for results and limitations.
