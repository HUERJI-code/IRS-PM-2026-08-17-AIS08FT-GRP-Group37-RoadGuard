# Chroma/E5 retrieval acceptance (2026-10-21)

Owner: A, extending C's merged assistant. Baseline: main commit
`dd23ca7e44b21fa2520fec2c8bac0f05335dc8cf` (PR #33). This record concerns local
retrieval; it does not claim real GPT answer-quality acceptance.

## Configuration and stored evidence

- ChromaDB 1.5.9, ONNX Runtime 1.31.0, tokenizers 0.23.3; CPU execution.
- Public `intfloat/multilingual-e5-small`, pinned revision
  `614241f622f53c4eeff9890bdc4f31cfecc418b3`; verified official model/tokenizer hashes.
- 384 dimensions; masked mean pooling and L2 normalization; E5 query/passage prefixes.
- Knowledge v12: eleven documents, forty parent sections, 57 stored vector passages.
- 320-token windows with 48-token overlap; parent sections are reconstructed after
  ranking so a table row or limitation is not lost at a child boundary.
- Cosine similarity candidate cutoff 0.78; top five distinct parent citations in
  the diagnostic comparison. This cutoff is a heuristic, not calibrated accuracy.

The [retrieval record](retrieval.json) contains every query, expected citation,
returned source, score and timing. Both methods use the same current knowledge
corpus. The lexical implementation is loaded from the pinned baseline commit by
the [evaluation script](../evaluate_retrieval.py).

| Diagnostic set | Lexical baseline | Chroma/E5 |
| --- | --- | --- |
| Existing 30 specifications: at least one expected citation in top five | 28/30 | 26/30 |
| Eight additional English/Chinese paraphrases: expected citation in top five | 2/8 | 7/8 |
| Three unrelated/noise inputs: no candidates returned | 2/3 | 1/3 |

These small synthetic sets are exploratory checks, not an independent benchmark
or answer-accuracy measurement. Some original cases require live plans or refusal;
finding a static citation cannot answer them by itself. Chroma/E5 improves this
paraphrase sample but does not dominate the lexical baseline. Stock advice and
random-looking text still retrieve candidates at the chosen cutoff. Real-model
refusal and semantic sufficiency remain unverified. Do not equate similarity with
correctness or use these ratios as Precision/Recall for YOLO.

The maximum serialized GPT context for the thirty static questions, using the
normal eight-hit query path, was 14,814 characters against the existing 24,000
limit. This is specific to these queries; large saved plans can still exceed it.

## API and storage verification

The [HTTP smoke record](http-smoke.json), generated by
[smoke_vector_api.py](../smoke_vector_api.py), uses a disposable business database,
real login/CSRF checks, the real local E5 model and the persistent Chroma index.
Two English/Chinese searches and one answer request passed. The answer request
used an explicitly injected GPT provider double. The business database was
unchanged by these three requests. No API key or real user account was used.

Targeted automated checks passed for Chroma persistence across processes,
idempotent builds, stale versions, changed encoders, interrupted-build recovery,
tampered documents/metadata, parent-table reconstruction, missing models, token
bounds, pooling and existing assistant role/change flows. CI embedding doubles
are labeled and are not included as real semantic results.

Full backend regression: 1,150 tests passed and two were skipped on Python 3.12.14
in 363 seconds. Both skips require OS permission to create symbolic links. The
run used temporary test databases and no paid services.
Frontend verification: 166 tests passed; ESLint, TypeScript and the Vite build
passed. The existing large-bundle warning remains. OpenAPI matches the generated
frontend snapshot. Existing Python package versions, including PyTorch and
Ultralytics, were unchanged; `pip check` passed.

## Reproduction

Follow [vector setup](../../../backend/roadguard/assistant/VECTOR_RETRIEVAL.md), then
run from the repository root:

```powershell
.\.venv\Scripts\python.exe SystemCode/experiments/assistant/evaluate_retrieval.py --output SystemCode/experiments/assistant/chroma-20261021/retrieval.json
.\.venv\Scripts\python.exe SystemCode/experiments/assistant/smoke_vector_api.py --output SystemCode/experiments/assistant/chroma-20261021/http-smoke.json
.\.venv\Scripts\python.exe -m pytest SystemCode/tests -q
```

Runtime vector segments, the embedding model/tokenizer and all Dataset contents
remain local and ignored. Only source, documentation and small textual evidence
belong in Git. The fourteen pre-existing YOLO work files are separate from this
change.
