# RoadGuard Jurong 项目范围与 NUS-ISS 模拟调度起点

版本：1.0 · 日期：2026-10-12 · 业务维护人：A（项目发起人）。

RoadGuard 首版将维修任务限定在 **Jurong East 与 Jurong West 两个规划区**，四支工程队从 **NUS-ISS** 统一出发。NUS-ISS 位于任务区域之外，因此系统须分别处理任务范围、基地位置和行驶路径：任务在区域内，指定基地允许在区域外，路线可以跨越区域边界。

本文件保留第 1 步的范围设计和静态资料核验记录。后续[第 6 步](INSPECTION_REVIEW_TASK_WORKFLOW.md)已实现任务点的多边形校验与巡检/任务保存；道路类型仍由调用者声明，未接入道路网络核验。NUS-ISS 是用户指定的真实地点，但调度用途、工程队、维修部门与任务均为课程模拟，不代表学校实际承担道路维修或认可该模拟。

## 1. 首版范围决定

| 项目 | 首版约定 |
| --- | --- |
| 任务服务区域 | URA Master Plan 2025 中 `JURONG EAST` 与 `JURONG WEST` 的多边形并集 |
| 区域面积 | 约 **32.55 km²**，包含区域内各种土地用途，不等于可维修道路面积 |
| 调度起点 | **NUS-ISS，25 Heng Mui Keng Terrace, Singapore 119615** |
| 基地坐标 | 纬度 `1.292149`，经度 `103.776551`，WGS84 |
| 工程队 | `crew-01`、`crew-02`、`crew-03`、`crew-04`；共用一个起点 |
| 分配范围 | 四队均可服务整个任务区域，不按 East／West 预先分队 |
| 任务类型 | 区域内普通公共机动车道路上的模拟道路损坏维修任务 |
| 主要实验规模 | 10／15／20 个维修任务，基地不计入任务数量 |
| 出发行程 | 必须计入 NUS-ISS 到每支有任务队伍的首个任务点的行程 |
| 收工返基地 | 尚待后续调度规则确定；示例配置保留 `null` |

选择这两个相邻规划区，可以给“Jurong”提供可检查、可复现的边界，又保留四队跨区域分配和访问排序的实验空间。这是本项目的范围选择；不将日常语言中的整个“Jurong”都纳入，也不因基地在区域外而扩大维修任务范围。

## 2. Jurong 的具体地理边界

### 2.1 纳入与排除

| 官方规划区名称 | 代码 | 数据中的面积 | 本项目用途 |
| --- | --- | --- | --- |
| JURONG EAST | JE | 17.8695 km² | 可安排符合道路条件的维修任务 |
| JURONG WEST | JW | 14.6804 km² | 可安排符合道路条件的维修任务 |
| 合计 | — | 32.5499 km² | 报告和展示四舍五入为 32.55 km² |

**BOON LAY、PIONEER、TUAS、BUKIT BATOK、CLEMENTI、QUEENSTOWN 等其他规划区不属于任务服务区域。** 道路、车站或建筑名称中出现 “Boon Lay”“Pioneer”“Jurong”等字样，不能代替坐标判断；名称与规划区并非一一对应。

区域内只接受普通公共机动车道路上的任务。首版排除高速公路主线及匝道维修任务、私有或限制进入的内部道路、停车场及校园内部道路、步行道、自行车道、湖面及公园非机动车道路，以及尚未开放的规划道路。这些是项目约定，规划区边界文件本身不包含道路类型和车辆通行权限。

### 2.2 唯一边界资料

| 字段 | 值 |

| `scope_version` | `jurong-je-jw-mp2025-v1` |

| 数据时期／目录更新日 | 2025-12／2026-02-27 |

| 本地文件 | [jurong-boundary-mp2025.geojson](geography/jurong-boundary-mp2025.geojson) |
| 文件内容 | 两个原始 Feature；保留来源属性和全部坐标，无边界简化 |
| 坐标规则 | WGS84 十进制度；GeoJSON 坐标数组为 `[longitude, latitude]` |

未来的任务校验使用两个多边形的并集。点位于任一多边形内部或边界上，均通过地理范围校验，即采用 **covers** 语义；仍须满足道路类型和任务规则，落在多边形内不等于一定可维修。

前端显示可参考外接矩形 `[west, south, east, north]`：

```text
[103.674932, 1.296503, 103.757281, 1.364348]
```

该矩形只用于定位视图。不能用矩形代替实际多边形校验，否则会把范围外地点误收进来；也不能只用这个矩形设置最终地图视野，因为它不包含 NUS-ISS。

三名成员使用仓库内同一份冻结文件，不在每次运行时各自下载“最新边界”。未来更新来源或调整范围时，由 A 同步版本、配置、任务样例和受影响的实验。URA 将该数据定位为指示性规划边界，本项目不将其解释为法定维修管辖区。

这是**建筑地址参考点，尚未验证为车辆可进入的实际入口**。B 接入道路行程服务时，需要检查出发和抵达路径能否接到可通行道路；如需改用入口点，应由 A／B 记录依据并更新基地版本、配置和地图。GA 与 Greedy 必须共用同一基地坐标，不能各自采用不同的道路吸附点而不说明。

四队使用同一基地，并不产生四个不同的地理起点。是否要求返基地、班次时长和共同开始时刻，在后续调度规则中确定。

## 4. 范围校验与行驶规则

| 对象 | 规则 | 示例结果 |
| --- | --- | --- |
| 维修任务点 | 必须被 JE／JW 多边形并集覆盖，并满足道路条件 | Jurong 范围外的任务不能进入本次有效调度输入 |
| 固定基地 | 允许指定的 `depot-nus-iss` 在范围外 | NUS-ISS 不因不在 Jurong 内而被任务校验器拒绝 |
| 任意其他基地 | 不自动获得范围外例外 | 后续新增或移动基地属于范围变更 |
| 行驶路径 | 可经过范围外的合法可通行道路 | 允许从 NUS-ISS 驶入 Jurong，不将路线强行裁剪到多边形内 |
| 高速公路 | 首版不在主线或匝道安排维修任务；通勤可使用车辆获准通行的道路 | “禁止高速维修任务”不等于“禁止路线走高速” |

A 负责任务位置的业务校验；B 负责基地配置、路线可达性及行程数据；C 同时展示任务边界、基地和路线。不把任务校验直接套用到基地，也不把整个规划区多边形当成道路网络。

模拟维修任务必须明确标记。RDD2022ES 图片与 Jurong 模拟任务坐标是不同来源：可以用于演示流程，但不得声称图片在对应坐标实地拍摄。后续固定任务集应选择可核对的道路位置，不在多边形内任意撒点后直接当成道路任务。

## 5. 对四队调度及 GA 评估的影响

N 个位置互异的维修任务加一个共用基地，形成 N+1 个地理节点；10／15／20 任务的标准实验分别对应 11／16／21 个节点。即使四队同地出发，也仍需保留四支队伍的状态和独立任务顺序。若未来允许任务坐标重合，须保持任务 ID 独立，并在矩阵节点映射中说明如何去重。

B 生成行程矩阵时必须覆盖基地与任务之间的方向性行程，并满足以下条件：

1. 每支有任务的队伍，行程从 NUS-ISS 开始；首段通勤纳入总行程时间、到达时间和相关班次计算。
2. 返基地策略目前未定。后续设为需要返回时，纳入最后任务到 NUS-ISS 的行程；设为不需要返回时，明确完工口径。`null` 代表未决定，不能静默当作 `false`。
3. GA 与 Greedy 使用相同任务、基地、矩阵、开始时刻和返基地策略。
4. 不可达或 API 失败不能作为零分钟行程；真实道路矩阵与模拟矩阵分别标记并保存来源。
5. 没有实际行程数据之前，不填写确定通勤分钟数，也不以地图直线距离代替道路耗时。

缩小地理范围有助于控制演示和采集工作，但 **GA 计算耗时不会仅因地区更小或队伍更多就必然下降**。任务数量、编码、种群、迭代次数和约束仍影响求解规模。工程队运营行程、GA 运行耗时、外部 API 用量分别测量，不提前宣称节省金额或性能提升。

## 6. 三人对接与配置约定

| 负责人 | 本步骤提供的资料 | 后续模块需要落实的行为 | 对接对象 |
| --- | --- | --- | --- |
| A：视觉与业务规则 | 本范围说明、冻结边界、基地参数和示例配置 | 任务地理校验；核对道路任务样例；标记模拟来源；统筹后续范围变更 | B 接收合法 Task 和同版本配置；C 接收范围说明及位置错误反馈 |
| B：四队调度 | 共用基地 ID、坐标、四队 ID、范围外基地例外 | 验证车辆入口和道路可达性；计入首段通勤；提出返基地／班次规则；统一矩阵与节点映射 | 向 A 反馈不可达位置，向 C 提供基地、顺序和行程来源 |
| C：界面与助手 | 边界 GeoJSON、基地 GeoJSON、示意图及展示文案 | 地图同时容纳 Jurong 和 NUS-ISS；区分基地与任务；显示模拟起点；助手解释区域外出发的原因 | 使用 A 的业务范围、B 的实际规划结果，避免自行计算第二套规则 |

[project.example.json](../SystemCode/config/project.example.json) 已表达本次设计。`geojson_path` 均相对**仓库根目录**，不是相对配置文件所在目录；未来由 A 的统一配置加载器解析，前端地图文件的提供方式由 A／C 在接口阶段约定。

配置现由共享后端在启动时读取，第 6 步校验冻结范围版本与路径。`study_boundary` 描述冻结范围；`allowed_outside_task_service_area` 只适用于当前指定基地；`routes_may_leave_study_area` 是未来路径规则；`return_to_depot: null` 保留待定业务决定。读取这些字段不表示规划器已实现。

本次完成“Jurong 范围与模拟起点”这一子步骤，**M0 尚未全部完成**。接下来由 A 统筹任务字段、标签与规则映射、置信度分流、维修时长和期限定义；B 提出班次、返基地策略、指标口径及优化约束；C 核对地图与表单所需字段。实现前再形成共同接口样例。
